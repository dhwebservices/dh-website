HQ day one

By the end of today, the new HQ screens are built with example data on a test link: the menu, Today, Clients, a client page, Jobs and the Inbox. Nothing you do today touches the live portal.

Branch: hq/buildTest link: hq-build.dh-portal-v2.pages.dev/hqFull plan: DH HQ Plan

How today works

Five sessions, one branch

You'll start a fresh Claude chat for each screen. Each chat starts with a prompt from this page: copy it, paste it, press Enter. Claude builds the screen and gives you the test link. You check it against the mockups in the plan, then tick it off here.

Everything goes on one branch called hq/build, so there's one test link all day. The ticks on this page are saved in your browser only.

Today's three rules

  • If Claude asks to merge, publish, or go to main: say no.
  • If Claude wants to change sign-in, permissions, payments, database tables or keys: say no and message David.
  • Everything uses example data today. Real clients come later, once David has done his part.

If something goes wrong

What to say to Claude

What happensWhat to do
It doesn't look like the mockupTake a screenshot and paste the prompt below.
Claude says it needs the database, a key or a new tableSay: "Use example data from src/hq/exampleData.js as docs/HQ.md says. Write down what real data this will need for David."
Claude asks to merge, publish, open a pull request, or use mainSay: "No. Stay on hq/build."
The build fails, or the test link shows a blank pageSay: "The build failed / the link shows a blank page. Find out why and fix it on hq/build."
The test link still shows the old versionWait two minutes and refresh. A new version takes 1 to 3 minutes to appear.
Sign-in on the test link failsMessage David. Keep building; check the screens when it works.
Claude seems confused or goes round in circlesStart a new chat and paste that session's prompt again. Nothing is lost: the work is saved on the branch.
Claude wants to change sign-in, permissions or paymentsSay no, and message David what it wanted.
